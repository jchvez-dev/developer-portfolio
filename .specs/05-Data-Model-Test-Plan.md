# Data Model Design & Test Plan

## Project: Core Engineering Portfolio & Polyglot Microservices Ecosystem

## 1. Storage Data Model Design (MinIO / S3 Topology)

Since the architecture decouples persistent binary files from the execution runtimes, the local S3-compliant storage layout is structured into highly specific, isolated access buckets.

```Plaintext
minio-root/
├── system-assets/       [Read-Only] Shared canvas background templates and static fonts.
├── user-uploads/        [Read-Write] Images uploaded by users via the canvas interface.
└── production-exports/  [Read-Write] High-res compiled images generated by the PHP microservice.
```

### 1.1 Object Naming & Path Conventions
- **User Asset Path:** `user-uploads/{session_id}/{uuid_v4}.{extension}`
    - _Example:_ `user-uploads/sess_89412/a1b2c3d4-e5f6-7a8b-9c0d-e1f2a3b4c5d6.jpg`
- **Compiled Output Path:** `production-exports/{job_id}.png`
    - _Example:_ `production-exports/canvas_job_8973129.png`

## 2. CKEditor Content Schema & Sanitization Strategy
Allowing raw HTML payloads from client-side instances like CKEditor poses massive security and parsing risks (XSS / Render injection). The system enforces a strict token schema whitelist at the API Gateway level (NestJS) before hitting the internal rendering service.

### 2.1 Whitelisted HTML Tags & Properties

The serialization pipeline blocks any layout containing tags outside this verified matrix:

|**Element**|**Allowed Tags**|**Allowed Attributes**|**Style Mappings**|
|---|---|---|---|
|**Paragraph**|`<p>`|`style`|`text-align`, `line-height`|
|**Emphasis**|`<strong>`, `<b>`, `<em>`, `<i>`|None|Font weight / Font style alterations|
|**Structure**|`<span>`|`style`|`color`, `font-family`, `font-size`|

### 2.2 Microservice Parsing Strategy
- **Data Flow:** NestJS processes the string text via an HTML sanitizer module ➔ Strips out harmful elements (e.g., `<script>`, `<iframe>`, `onload` hooks) ➔ Wraps verified nodes into an explicit structure ➔ Hands down clean blocks to the PHP Image Engine.
## 3. Comprehensive Test Plan

This verification matrix targets integration bottlenecks, microservice handshakes, and execution performance under high workloads
### 3.1 Integration Test Suite (Microservice Handshake)
- **Test Case IT-1: Perimeter Connectivity Check**
    - _Objective:_ Confirm that `backend-php` ignores external public traffic but accepts local ingress.
    - _Method:_ Execute `curl http://localhost:8000/internal/render` from host machine (Expect: `Connection Refused`). Execute the same call inside the `backend-nest` container shell (Expect: `200 OK` or routing hit).
- **Test Case IT-2: Storage Write Verification**
    - _Objective:_ Ensure the PHP service has active access-keys to persist assets to MinIO.
        
    - _Method:_ Trigger mock render job ➔ Verify Object presence in `production-exports` bucket inside the MinIO visual terminal (`http://localhost:9001`).
### 3.2 Functional Test Suite (Edge Cases & Failure Resilience)
- **Test Case FT-1: Malicious Script Ingress (XSS Blocking)**
    - _Input Payload:_ `{"content": "<script>alert('hack')</script><strong>Senior</strong>"}`
    - _Expected Behavior:_ NestJS intercepts payload ➔ Rejects request or sanitizes input, passing only `<strong>Senior</strong>` down to the canvas assembler ➔ Status code `422` or clean render execution.
- **Test Case FT-2: Empty Asset Canvas Fallback**
    - _Input Payload:_ Missing background images or layers array set to empty `[]`.
    - _Expected Behavior:_ Gateway intercepts with a `400 Bad Request` schema payload error via `class-validator`, avoiding container system resource starvation.

### 3.3 Non-Functional Test Suite (Concurrency & Engine Safety)
- **Test Case NFT-1: Heavy Graphic Thread Isolation**
    - _Method:_ Execute a load test script sending 50 concurrent image compilation tasks to the API gateway while continuously prompting the AI Career Assistant chat node.
    - _Success Threshold:_ The AI Assistant token streaming experience maintains an uninterrupted, non-blocking flow (`< 200ms` initial response time), confirming that PHP-FPM's CPU-bound work does not lock the Node.js main thread loop.
