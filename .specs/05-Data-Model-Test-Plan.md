# Data Model Design & Test Plan

## Project: Core Engineering Portfolio & Polyglot Microservices Ecosystem

## 1. Storage Data Model Design (MinIO / S3 Topology)

Since the architecture decouples persistent binary files from the execution runtimes, the local S3-compliant storage layout is structured into highly specific, isolated access buckets.

```Plaintext
minio-root/
├── system-assets/        [Read-Only] Shared canvas background templates, static fonts, and CV documents.
├── user-uploads/         [Read-Write] Images uploaded by users via the canvas interface.
├── production-exports/   [Read-Write] High-res compiled images generated by the PHP microservice.
└── chat-history/         [Read-Write] JSON conversation logs persisted by the AI Career Assistant.
```

### 1.1 Object Naming & Path Conventions
- **User Asset Path:** `user-uploads/{session_id}/{uuid_v4}.webp`
    - _Example:_ `user-uploads/sess_89412/a1b2c3d4-e5f6-7a8b-9c0d-e1f2a3b4c5d6.webp`
- **Compiled Output Path:** `production-exports/{job_id}.png`
    - _Example:_ `production-exports/canvas_job_8973129.png`
- **Conversation Path:** `chat-history/conversations/{conversation_id}.json`
    - _Example:_ `chat-history/conversations/a1b2c3d4-e5f6-7a8b-9c0d-e1f2a3b4c5d6.json`

## 2. CKEditor Content Schema & Sanitization Strategy
Allowing raw HTML payloads from client-side instances like CKEditor poses massive security and parsing risks (XSS / Render injection). The system enforces a strict token schema whitelist at the API Gateway level (NestJS) before hitting the internal rendering service.

### 2.1 Whitelisted HTML Tags & Properties

The serialization pipeline blocks any layout containing tags outside this verified matrix:

|**Element**|**Allowed Tags**|**Allowed Attributes**|**Style Mappings**|
|---|---|---|---|
|**Paragraph**|`<p>`|`style`|`text-align`, `line-height`|
|**Emphasis**|`<strong>`, `<b>`, `<em>`, `<i>`|None|Font weight / Font style alterations|
|**Structure**|`<span>`|`style`|`color`, `font-family`, `font-size`|

### 2.2 Microservice Parsing Strategy
- **Data Flow:** NestJS processes the string text via an HTML sanitizer module ➔ Strips out harmful elements (e.g., `<script>`, `<iframe>`, `onload` hooks) ➔ Wraps verified nodes into an explicit structure ➔ Hands down clean blocks to the PHP Image Engine.
## 3. Comprehensive Test Plan

This verification matrix targets integration bottlenecks, microservice handshakes, and execution performance under high workloads
### 3.1 Integration Test Suite (Microservice Handshake)
- **Test Case IT-1: Perimeter Connectivity Check**
    - _Objective:_ Confirm that `backend-php` ignores external public traffic but accepts local ingress.
    - _Method:_ Execute `curl http://localhost:8000/internal/render` from host machine (Expect: `Connection Refused`). Execute the same call inside the `backend-nest` container shell (Expect: `200 OK` or routing hit).
- **Test Case IT-2: Storage Write Verification**
    - _Objective:_ Ensure the PHP service has active access-keys to persist assets to MinIO.
        
    - _Method:_ Trigger mock render job ➔ Verify Object presence in `production-exports` bucket inside the MinIO visual terminal (`http://localhost:9001`).
### 3.2 Functional Test Suite (Edge Cases & Failure Resilience)
- **Test Case FT-1: Malicious Script Ingress (XSS Blocking)**
    - _Input Payload:_ `{"content": "<script>alert('hack')</script><strong>Senior</strong>"}`
    - _Expected Behavior:_ NestJS intercepts payload ➔ Rejects request or sanitizes input, passing only `<strong>Senior</strong>` down to the canvas assembler ➔ Status code `422` or clean render execution.
- **Test Case FT-2: Empty Asset Canvas Fallback**
    - _Input Payload:_ Missing background images or layers array set to empty `[]`.
    - _Expected Behavior:_ Gateway intercepts with a `400 Bad Request` schema payload error via `class-validator`, avoiding container system resource starvation.

### 3.3 Non-Functional Test Suite (Concurrency & Engine Safety)
- **Test Case NFT-1: Heavy Graphic Thread Isolation**
    - _Method:_ Execute a load test script sending 50 concurrent image compilation tasks to the API gateway while continuously prompting the AI Career Assistant chat node.
    - _Success Threshold:_ The AI Assistant token streaming experience maintains an uninterrupted, non-blocking flow (`< 200ms` initial response time), confirming that PHP-FPM's CPU-bound work does not lock the Node.js main thread loop.

### 3.4 Upload Test Suite (User Asset Pipeline)
- **Test Case UT-1: Valid Image Upload**
    - _Objective:_ Verify full pipeline accepts a valid PNG, processes it, and stores the result in MinIO as WebP.
    - _Method:_ POST multipart with a valid PNG file to `/api/v1/canvas/upload`.
    - _Expected:_ 201 response with `assetUrl` pointing to the `user-uploads/` bucket. Stored file is WebP format, max dimension 1920px.

- **Test Case UT-2: File Type Rejection**
    - _Objective:_ Reject non-image file uploads.
    - _Method:_ POST multipart with a `.txt` file to `/api/v1/canvas/upload`.
    - _Expected:_ 422 response with a file type validation error message.

- **Test Case UT-3: File Size Exceeds Limit**
    - _Objective:_ Reject files exceeding the 10MB size limit.
    - _Method:_ POST multipart with a file larger than 10MB.
    - _Expected:_ 422 response with a size validation error message.

- **Test Case UT-4: Resize Enforcement**
    - _Objective:_ Verify that large source images are resized to a maximum of 1920px on the longest side.
    - _Method:_ Upload a 4000x3000px image via the upload pipeline.
    - _Expected:_ The stored image in MinIO has a width of 1920px (maintaining aspect ratio) and is in WebP format.

- **Test Case UT-5: Internal Processing Isolation**
    - _Objective:_ Confirm that `/internal/process-upload` is not accessible from outside the Docker network.
    - _Method:_ Execute `curl http://localhost:8000/internal/process-upload` from the host machine.
    - _Expected:_ Connection refused.

### 3.5 Chat Test Suite (AI Career Assistant)
- **Test Case CT-1: SSE Token Streaming**
    - _Objective:_ Verify that the chat endpoint returns a valid SSE stream with token chunks.
    - _Method:_ POST to `/api/v1/chat` with `{"message": "Does Juan know React?"}`.
    - _Expected:_ Response with `Content-Type: text/event-stream` emitting `data: {"token": "...", "done": false}` chunks, ending with `data: {"token": "", "done": true}`.

- **Test Case CT-2: CV Context Injection**
    - _Objective:_ Verify that the chat response is grounded in the CV stored in MinIO.
    - _Method:_ POST a question about Juan's experience, e.g., `{"message": "What technologies does Juan use?"}`.
    - _Expected:_ Response tokens reflect the content of `system-assets/cv-juan-chavez.md` (e.g., mentions React, NestJS, Docker, etc.).

- **Test Case CT-3: Conversation Persistence**
    - _Objective:_ Verify that conversation history is persisted across messages.
    - _Method:_ Send first message with `conversationId: "test-conv-1"` -> Send second message with same `conversationId`.
    - _Expected:_ The second response acknowledges context from the first. A JSON file exists at `chat-history/conversations/test-conv-1.json` in MinIO.

- **Test Case CT-4: Conversation History in MinIO**
    - _Objective:_ Verify the stored conversation JSON has the correct schema.
    - _Method:_ Check `chat-history/conversations/{conversationId}.json` in MinIO after a chat interaction.
    - _Expected:_ File contains valid JSON with `conversationId`, `createdAt`, `updatedAt`, and `messages` array alternating `user` and `assistant` roles.

- **Test Case CT-5: Missing API Key Fallback**
    - _Objective:_ Verify graceful error handling when GROQ_API_KEY is not configured.
    - _Method:_ Remove `GROQ_API_KEY` from environment and POST to `/api/v1/chat`.
    - _Expected:_ 200 OK response with SSE error token or the stream completes with an error message.
